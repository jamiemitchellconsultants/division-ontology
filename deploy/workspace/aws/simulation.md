# AWS deployment simulation

The Terraform module describes CloudFront and private S3 for the browser app, API Gateway and .NET Lambda for the API, two scheduled worker handlers, private S3 for bundles, and Docker PostgreSQL 16 with AGE and pgvector on private EC2. Terraform reads the four database secret ARNs. The EC2 service and the Lambda functions resolve their secrets at runtime. Entra app registrations, redirect URIs and workspace roles are owned by the identity administrator.

Run `./verify-terraform.sh` to initialize the pinned provider, validate and run mocked plans. Run the repository's `deploy/workspace/verify.sh aws-sim` for the Lambda and PostgreSQL scenario. Both use fixture values. The AWS target has only been exercised in local simulation.

## Artefact and operational inputs

- `package.sh` builds the two managed-runtime Lambda ZIPs and the static `wwwroot`. Supply its output via the private regional artefact bucket and `web_directory` inputs. The database and migration-worker images come from the same reviewed build, mirrored to the regional private ECR and pinned by digest.
- Supply an Amazon Linux 2023 x86-64 AMI compatible with the NVMe EBS mount path and the Docker and AWS CLI commands in the bootstrap. Use the four Secrets Manager entries under the workspace account and region, with `username` and `password` fields. The bootstrap expects the fixed service names `workspace_admin`, `workspace_api_user`, `workspace_publisher_user` and `workspace_indexer_user`, and URL-safe generated passwords of at least 24 characters. The database admin password must match the value that initialized the retained PostgreSQL cluster.
- Configure the tenant's exact Entra v2 issuer, the API audience claim, the SPA client and the delegated API scope. Register the CloudFront callback URI output and the corresponding logout callback. Register the `entra_docs_redirect_uri` output (`https://<workspace_url>/api/docs/oauth2-redirect.html`) as a *Single-page application* redirect URI on the existing SPA app registration, beside `entra_redirect_uri`. The docs UI at `/api/docs` signs in with that registration and `entra_api_scope`, using the authorization code flow with PKCE. It needs no new app registration, role or secret. After deployment, run `deploy/workspace/verify-docs.sh https://<workspace_url> --expect-sign-in`. Assign the two workspace app roles on the API registration. The API enforces the roles on each request.
- Stage a content-addressed bundle in the private bucket through a separately authorized publisher. Give Terraform its manifest digest as `pending_manifest` to enable the scheduled publisher. One run stages the bundle, subsequent runs wait for baseline indexing, and activation is idempotent. Clear the digest after confirming activation. Use the same container worker for a bundle that exceeds the Lambda execution limit. Lambda connection capacity totals 16 across the three workloads. The default database budget is 24, leaving capacity for operator work.
- Keep the encrypted EBS data volume across instance replacement. The service waits for that volume, refuses a nonempty unknown filesystem, and starts PostgreSQL only after mounting the identified device. AWS launch, model access, secret policy, live Entra and CloudFront callbacks, and EBS behavior across a real host replacement remain to be verified with an AWS account.
